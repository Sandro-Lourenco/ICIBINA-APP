# 55 — V5.3 semantic invariants and runtime proofs

V5.3 closes gaps that syntax-only validators could not catch.

## Canonical invariants

`architecture-invariants.json` is machine-readable truth for product/database identity, DB roles, ORM/migration authority, MCP wrapper/profile and the canonical Asaas webhook ordering. `scripts/check-canonical-invariants.py` cross-checks those facts against operational files.

## Database proof

A fresh local PostgreSQL volume runs `database/bootstrap/00_roles.sh`. CI/release uses an isolated PostgreSQL service, migrates with `icibina_migrator`, runs the app with `icibina_app`, and proves that `icibina_app` cannot create a table.

## MCP isolation

The MCP process is launched through `scripts/postgres-mcp-wrapper.py`, which redirects postgres-mcp profile files to `.icibina/mcp-home`. This prevents the ICIBINA agent from enumerating unrelated saved profiles in the user's normal `~/.postgres-mcp` store. The role remains read-only and limited to `agent_inspection`.

## Plugin proof

`smoke-agent-skills.py --external` probes plugin-only skills (`ui-ux-pro-max` and official `fastapi`) so a local orchestrator cannot make a broken external plugin look healthy.

## Release proof

Release requires isolated DB migration, authorization/payment security markers, OpenAPI compatibility via a imagem imutável de oasdiff registrada em `release-images-lock.json`, CycloneDX SBOM generation and frontend/backend architecture fitness functions.
